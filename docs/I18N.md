# Internationalization (i18n)

How translated copy works in this template.

## Stack

- [`react-intl`](https://formatjs.io/docs/react-intl/) for
  `<FormattedMessage>` and `useIntl()`.
- A locale-cascading message loader at `src/i18n/intlUtility.js`
  (ported from the FL Poly account-details extension).
- One JSON file per locale in `src/i18n/`, with `en.json` as the
  canonical baseline.

## Provider

`src/i18n/ReactIntlProviderWrapper.jsx` exports
`withIntl(Component)` — a HOC that wraps any component in a
`<RawIntlProvider>` configured for the user's locale (read from
`useUserInfo().locale`). Every card and page in this template
ends with:

```jsx
export default withIntl(withStyles(MyCard, styles, { name: 'MyCard' }));
```

`withIntl` is the **outermost** HOC. Order matters — `withStyles`
needs to be inside so the intl context is available when styles
compute.

## Locale cascade

`getMessages(userLocale)` in `src/i18n/intlUtility.js` cascades:

1. Try `src/i18n/<exact-locale>.json` (e.g. `en-US.json`).
2. Fall back to `src/i18n/<language>.json` (e.g. `en.json`).
3. Fall back to `en.json` (the baseline).

Returns the merged messages object — locale messages override
English where they differ; missing keys fall back to English.

## Adding a new locale

1. Copy `src/i18n/en.json` → `src/i18n/<locale>.json` (use BCP 47:
   `es`, `fr`, `de`, or region-specific like `pt-BR`).
2. Translate the values; keep the keys identical to `en.json`.
3. No build-time registration needed — `intlUtility.js`
   `require()`s the file dynamically based on `useUserInfo().locale`.

## Adding a new key

1. Add it to `src/i18n/en.json` first (canonical baseline).
2. Use it in code:

```jsx
intl.formatMessage({
    id: 'mySection.myKey',
    defaultMessage: 'Same as in en.json',
})
```

The `defaultMessage` is a safety net — if `en.json` is somehow
missing the key, the inline default still renders.

3. (Optional) Add the translated value to each `<locale>.json`
   file.

## Naming convention

```
<surface>.<feature>.<role>
```

| Surface prefix | Used for |
|----------------|----------|
| `card.<cardName>.*` | Card-specific copy. |
| `page.<pageName>.*` | Page-specific copy. |
| `hello.*` | (Convention from HelloUserCard — short prefix accepted for tiny vocabularies.) |
| `common.*` | Reusable strings shared across surfaces (e.g. `common.copied`). |
| `ethos.error.*` | Error normalization in `src/utils/ethos/errors.js`. |

Examples (from `en.json`):

| Key | Where used |
|-----|-----------|
| `hello.morning` | HelloUserCard greeting. |
| `card.ethosFetch.empty.title` | EthosFetchCard empty state title. |
| `card.configurable.color.primary` | ConfigurableCard color preset name. |
| `card.pageLink.choice.body` | PageLinkCard choice dialog body. |
| `common.copied` | Shared "Copied" affordance. |
| `ethos.error.network` | Error normalization. |

## Plurals + variables

Use ICU MessageFormat:

```json
{
    "card.ethosFetch.announce.loaded": "{count, plural, one {# term loaded} other {# terms loaded}}."
}
```

```jsx
intl.formatMessage(
    { id: 'card.ethosFetch.announce.loaded' },
    { count: 5 },
)
// → "5 terms loaded."
```

## Date / number formatting

`useIntl()` exposes `formatDate`, `formatNumber`,
`formatRelativeTime`, etc. The locale is already wired via the
provider:

```jsx
intl.formatDate(date, { year: 'numeric', month: 'short', day: 'numeric' });
intl.formatNumber(amount, { style: 'currency', currency: 'USD' });
```

Don't import `Intl.DateTimeFormat` directly — the wrapper
guarantees the user's locale is used.

## Testing

Tests render components inside the same `<RawIntlProvider>`. The
mock at `__mocks__/@ellucian/experience-extension-utils.js`
returns a fixed `locale: 'en-US'` from `useUserInfo()`. Override
per-test if you need to verify a non-English path:

```jsx
jest.mock('@ellucian/experience-extension-utils', () => ({
    useUserInfo: () => ({ locale: 'fr' }),
    // ... other hooks
}));
```

## Where translation work belongs

i18n is the responsibility of the adopting institution. The
template ships English. Add locales to your fork as your user
base requires.
